# AgentX Risk Validator -- Metric Inconsistency Diagnosis
Date: 2026-05-19
Phase: 5B.1

---

## Symptom

Two sources of model performance metrics exist and contradict each other:

| Source | Accuracy | ROC-AUC |
|---|---|---|
| `reports/validation_report.md` | 0.82 | 0.668 |
| `data/validation_outputs/performance_metrics.json` | 0.486 | 0.333 |

ROC-AUC of 0.333 is below random chance (0.5 expected for a random classifier on a balanced problem). A legitimate logistic regression trained on meaningful features should not produce this.

---

## Root Cause: Two Different Data Pipelines Were Used

### Pipeline A -- used when generating `validation_report.md`

```
main.py
  -> load_clean_data()       [reads CSV as-is, raw string labels]
  -> train_model(df_raw)     [LabelEncodes categoricals in-place, no StandardScaler]
     -> X: LabelEncoded, NOT StandardScaled
     -> y: raw strings ("Fully Paid", "Charged Off")
     -> LogisticRegression fits on unscaled data
     -> returns model, X_test_unscaled, y_test_raw
  -> evaluate_model(model, X_test_unscaled, y_test_raw)
     -> performance_agent converts string labels to 0/1
     -> evaluates model on SAME format it was trained on
     -> ROC-AUC: 0.668 (coherent)
```

### Pipeline B -- used when generating `performance_metrics.json`

This occurred when the Streamlit app was used (or when main.py was run after
`load_clean_data` was removed from `load_data.py`):

```
streamlit_app.py (or a later version of main.py)
  -> preprocess_uploaded_data(df)
     -> LabelEncodes categoricals
     -> StandardScales ALL numeric features (mean=0, std=1)
     -> encodes loan_status to 0/1
  -> evaluate_model(model_loaded_from_pkl, X_scaled, y_encoded)
     -> model was trained WITHOUT StandardScaling
     -> receives StandardScaled features it has never seen
     -> predictions are near-random
     -> ROC-AUC: 0.333 (worse than random due to scale mismatch)
```

---

## Secondary Cause: `load_clean_data` Missing from `load_data.py`

`main.py` imports `from utils.load_data import load_clean_data`, but the current
`utils/load_data.py` does not define `load_clean_data`. This means running `main.py`
in its current state would raise an `ImportError` immediately.

The function was either removed or renamed to `preprocess_uploaded_data` at some point
without updating `main.py`. This broke the main.py entry point.

## Files Involved

| File | Role in Inconsistency |
|---|---|
| `utils/load_data.py` | Missing `load_clean_data`; `preprocess_uploaded_data` applies StandardScaler |
| `utils/model_utils.py` | `train_model` does LabelEncoding but NO StandardScaler |
| `main.py` | Imports missing `load_clean_data`; currently broken |
| `agents/performance_agent.py` | Evaluates model on whatever X it receives |
| `reports/validation_report.md` | Generated by an older, coherent run |
| `data/validation_outputs/performance_metrics.json` | Generated by mismatched pipeline |

---

## Why Neither Reported Metric Is Safe To Cite

- **0.668 ROC-AUC (markdown):** From an older coherent run, but main.py is now broken
  (missing import). Cannot reproduce this number from current code.
- **0.333 ROC-AUC (JSON):** From a pipeline mismatch. The model was evaluated on data
  it was never trained on. This number reflects preprocessing inconsistency, not model quality.

Both numbers must be discarded and replaced by a verified run from a corrected pipeline.

---

## Correct Architecture (Implemented in Phase 5B.1)

```
One pipeline, used consistently for both training and inference:

  preprocess_uploaded_data(df)
    -> Drop ID columns
    -> Impute missing values (median for numeric, "Unknown" for categorical)
    -> LabelEncode categorical columns
    -> Encode loan_status to 0/1
    -> NO StandardScaler here (moved into model Pipeline)

  train_model(df_preprocessed)
    -> split into X_train, X_test, y_train, y_test
    -> Pipeline([("scaler", StandardScaler()), ("model", LogisticRegression())])
    -> fit Pipeline on X_train, y_train
    -> scaler is fit ONLY on training data (no leakage)
    -> save full Pipeline as model artifact (scaler + model together)

  evaluate_model(pipeline, X_test, y_test)
    -> pipeline.predict(X_test) -- scaler applied internally
    -> correct metrics computed
```

This architecture ensures:
- Identical preprocessing in training and inference
- No data leakage (scaler fit on train only)
- Reproducible results from either entry point
- Single saved artifact contains both scaler and model
```
